# Review, Approval, and Data Preconditions — v0.2.0

## 1. 三轮独立结构审查

只有普通 `AUDIT` 执行，并按顺序完成。输入中的 `review_rounds`、`review_inputs_complete`、`structure_summary`、`route` 和 `blockers` 都是非权威提示；Agent 必须根据实际结构重新判断。

### Round 1：命题与观众

检查：

- 只有一个主要任务；
- 一个公共主问题统摄全部主题；
- payoff 具体，并已由 Koda 选择；
- 核心判断是肯定式、可证伪并由 Koda 选择；
- 个人经历服务公共命题，而不是近况时间线；
- 受众处境与 desired change 有来源。

任一关键项不成立：`FAIL`。

### Round 2：因果与证据

检查：

- 章节存在递进关系，不是平级话题堆砌；
- 每个核心主张有 `PROOF`；
- 每个主要章节有 `PROOF`，唯一允许的纯逻辑章节除外；
- `ILLUSTRATION` 未被当作证明；
- 纯逻辑章节至多一个、标记 `INFERENCE`，且不独立承载核心判断；
- Koda 个人事实均有台账 ID 或当前轮确认事件，且 `allowed_uses` 精确支持当前用途；
- 包装事实与 claim map 一致；
- Commentary 的反方是目标观众或可信反对者真实会提出的主张，并说明哪部分成立。

反方只因“容易被驳倒”而存在、没有可信人群或来源依据，属于稻草人，Round 2 必须 `FAIL`。

任一关键项不成立：`FAIL`。

“最强证明是否出现过晚”由 Koda 判断。Skill 只报告首个 `PROOF` 的位置以及其前面有多少个未经证明的实质章节，不把任意百分比当成硬门。

### Round 3：留存与压缩

检查：

- 前 30 秒计划兑现包装；
- 没有自我介绍、片头、空洞背景或机械目录；
- 每章只有一个主要功能；
- 相邻两个无具体证明的章节被标记为“连续抽象风险”；
- 所有 open loop 都有真实问题并在后文兑现；
- 输入结构中不存在仍未处理的无证据、重复或只为时长存在的章节；
- 结尾兑现 payoff，并自然进入下一条；
- 不用固定 CTA 或固定 Re-hook 过门。

若被审查版本仍包含应删除或合并的章节，Round 3 为 `FAIL`。`AUDIT` 只能指出章节 ID 和修复路径，不得在同次运行中执行删除、合并或重排；修订版必须经 `REBUILD` 或用户修改后重新提交 AUDIT。

任一关键项不成立：`FAIL`。

## 2. READY 与 APPROVED

`READY_FOR_KODA_APPROVAL` 需要同时满足：

- mode=`AUDIT`；
- operation_scope=`STRUCTURE_WORK`；
- 三轮由本次 Agent 独立执行并均为 `PASS`；
- `blockers=[]`；
- 被审查的输入版本本身已满足全部门槛，而不是“假设修复后会通过”；
- 只有一个待最终批准的完整结构版本；
- 所有 Koda 个人事实已确认或从结构中移除。

`APPROVED_FOR_HANDOFF` 还需要：

- Koda 明确 `STRUCTURE_APPROVED` 事件；
- 包装 `LOCKED`，并有 `PACKAGING_LOCKED` 事件；
- payoff 与核心判断有明确选择事件；
- 无未解决的事实或证据问题。

没有明确事件时，即使结构质量很高，也只能是 `READY_FOR_KODA_APPROVAL`。

`REJECTED` 只由 `VIDEO_REJECTED` 事件触发。

## 3. 数据前提 → 允许结论

v0.2.0 不执行完整 RETENTION_REVIEW，但任何发布后数据请求必须使用 `DATA_PRECONDITION_CHECK_ONLY` 覆盖层，并遵守以下边界：

| 想判断什么 | 最低数据前提 | 缺失时允许输出 |
|---|---|---|
| 包装吸引是否变化 | 同一时间窗口的 impressions、CTR、流量来源、包装版本 | 写入 `missing_data[]`；不能归因 |
| 前 30 秒是否出现明显流失 | 第 30 秒留存或完整留存曲线，且有视频时长与时间窗口 | `UNDETERMINED` |
| 某章节是否对应退出 | 带时间戳的留存曲线 + 章节时间码 + 版本一致 | `UNDETERMINED` |
| 平均观看比例 | 视频时长 + 平均观看时长 | 可计算比例；不能解释原因 |
| 与频道基线粗比较 | 同片型、同流量来源、可比窗口的历史基线 | 没有可比基线则 `UNDETERMINED` |
| 连续观看 / 下一条承接 | end screen 或下一条点击、播放列表或连续观看数据 | `UNDETERMINED` |

仅有总观看量与平均观看时长时：

- 若有视频时长，可计算平均观看比例；
- 若有可比同片型基线，可做粗比较；
- 开头原因、章节原因、退出位置与包装因果全部 `UNDETERMINED`；
- 将留存曲线、章节时间码及其他必要前提逐项写入 `missing_data[]`；
- 不得生成“观众因为某段抽象所以离开”一类叙事；
- 不得加入 `EVIDENCE_GAP`，因为这里缺的是分析数据，不是视频主张或章节的 `PROOF`。

Adam 的 30 秒 75% 只作为外部参考，不是统一通过线。

## 4. 结构假设预注册与学习门槛

每条视频可在 `tested_hypotheses[]` 预注册一项主要结构变量。发布后只记录：

- 数据事实；
- 可能解释；
- 不能确认；
- 干扰因素；
- 下一轮只测试什么。

从观察升级为结构规则，至少需要：

1. 三条或以上同片型视频出现方向一致的信号；
2. 使用可比数据窗口与指标；
3. 每条都记录主要干扰因素；
4. 假设在视频发布前预注册，或明确标记为事后观察；
5. 到复核日期后仍成立；
6. Koda 明确批准升级。

v0.2.0 不自动升级规则。单条视频表现不能固化为永久模板，`DATA_PRECONDITION_CHECK_ONLY` 也不得执行规则升级。
