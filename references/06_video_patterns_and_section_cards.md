# Video Patterns, Source Cards, and Section Cards

结构名称首先是工作工具，不是效果保证。对外说明统一使用中文名；英文名和缩写只留在内部审计包。每张说明卡都要区分外部理论、外部方法改编和本项目工作规则。

## 1. 母结构说明卡

### 结构说明卡：COMMENTARY

- 中文名：观点论证型
- 作用：用事实、案例、反方和边界，带观众形成或修正一个判断。
- 适用场景：反常识观点、常见说法的反驳、创作者判断、以个人经历证明公共问题。
- 不适用场景：观众主要想完成一个明确操作，或任务只是执行前实验登记。
- 来源性质：由外部方法改编
- 理论或方法来源：Stephen Toulmin《The Uses of Argument》关于主张、依据、限定与反驳的论证分析：https://doi.org/10.1017/CBO9780511840005 ；Carolyn R. Miller 关于体裁回应社会行动目的的研究：https://doi.org/10.1080/00335638409383686 。
- 本 Skill 改编：保留“判断—证明—真实反方—限定后结论”的论证责任，但不照搬完整 Toulmin 字段，也不把个人经历本身当作公共命题。

母结构候选：公共问题 → Koda 已确认的判断 → 真实证明 → 真实最强反方 → 反方成立的部分 → 限定后的判断 → 观众可迁移的方法 → 下一条承接。

### 结构说明卡：EDUCATIONAL

- 中文名：行动教学型
- 作用：让观众看完能够完成一个清楚的动作、流程或工作结果。
- 适用场景：软件操作、工作流演示、分步方法和可验证的实作结果。
- 不适用场景：主要目标是改变观点，或每个步骤没有可展示的例子与结果。
- 来源性质：由外部方法改编
- 理论或方法来源：M. David Merrill 的教学首要原则强调真实问题、示范、应用与整合：https://doi.org/10.1007/BF02505024 ；Sweller 与 Cooper 的 worked-example 研究支持先展示完整示例再让学习者解决问题：https://doi.org/10.1207/s1532690xci0201_3 。
- 本 Skill 改编：把“结果预览—前置条件—步骤—示例—常见错误—最终结果”变成视频母结构，但不声称这一顺序对所有受众都最优。

母结构候选：问题钩子 → 成品或结果预览 → 看完能完成什么 → 前置条件 → 3—5 个步骤 → 示例或操作证据 → 常见错误 → 最终结果 → 下一课。

### 结构说明卡：PUBLIC_EXPERIMENT

- 中文名：执行前实验登记型
- 作用：在行动开始前写清问题、基线、假设、规则、指标、观察窗口和干扰因素，避免事后改口。
- 适用场景：一个公开实验尚未开始，任务明确要求预先登记判断方法。
- 不适用场景：实验已经完成后的结果片、普通教程或单纯观点表达。
- 来源性质：有外部理论依据
- 理论或方法来源：Nosek、Ebersole、DeHaven 与 Mellor 对 preregistration 区分事前确认性判断与事后探索性发现的说明：https://doi.org/10.1073/pnas.1708274114 。
- 本 Skill 改编：v0.2.0 只提供季初实验的事前登记，不假装已经支持完整实验结果片，也不把预注册当成结果证明。

命中后使用 `10_public_experiment_preregistration.md`，不再同时生成观点型或行动教学型章节。

## 2. 章节组织方式说明卡

### 结构说明卡：STP

- 中文名：背景—张力—回报
- 作用：先交代必要背景，再展示一个真实未解决问题，最后给出这一段的回答或推进。
- 适用场景：存在真实矛盾、认知缺口或未解决问题的观点章节。
- 不适用场景：没有真实张力、只是列信息，或为了制造悬念故意隐瞒关键事实。
- 来源性质：由外部方法改编
- 理论或方法来源：Loewenstein 的信息缺口理论解释已知与未知之间的差距如何引发好奇：https://doi.org/10.1037/0033-2909.116.1.75 ；George Blackman 的公开视频写作实践把 Setup / Tension / Payoff 用于章节组织：https://writewithai.substack.com/p/write-a-killer-youtube-script-like 。
- 本 Skill 改编：`STP` 是项目采用的工作缩写，不是 Loewenstein 提出的学术模型；张力必须真实且最后兑现。

### 结构说明卡：PEIL

- 中文名：观点—解释—示例—落地
- 作用：先说清一个要点，再解释原因，用例子展示，最后告诉观众如何使用。
- 适用场景：教学步骤、概念解释和需要示范的知识单元。
- 不适用场景：主要靠冲突推进的故事，或没有实际例子与应用的抽象议论。
- 来源性质：由外部方法改编
- 理论或方法来源：Merrill 的示范、应用与整合原则：https://doi.org/10.1007/BF02505024 ；Dan Martell 的公开生产方法是本项目采用该四步缩写的实践来源，冻结输入未提供可核查公开链接。
- 本 Skill 改编：`PEIL` 的精确顺序与缩写属于项目工作规则，不宣称 Merrill 原文提出这四个英文词。

### 结构说明卡：VALUE_LOOP

- 中文名：情境—应用—重新理解
- 作用：把一个知识点放入具体使用情境，展示如何应用，再帮助观众形成更完整的理解。
- 适用场景：知识迁移、从旧经验转到新场景、解释一个方法为何在现实中有用。
- 不适用场景：纯步骤教学、纯事实播报或没有实际情境的抽象概念。
- 来源性质：由外部方法改编
- 理论或方法来源：Brown、Collins 与 Duguid 关于知识与活动、情境和文化相联系的 situated cognition 研究：https://doi.org/10.3102/0013189X018001032 ；Laurentickner 的 Value Loop 是本项目的实践参考，冻结输入未提供可核查公开链接。
- 本 Skill 改编：Context → Application → Framing 的精确三步是项目编辑工具，不是 situated cognition 论文中的命名模型。

### 结构说明卡：PLAIN

- 中文名：直接说明
- 作用：不制造悬念，直接交代这段的功能、事实、证据和观众结论。
- 适用场景：边界说明、必要背景、简短过渡和没有真实冲突的事实段落。
- 不适用场景：需要分步教学、论证复杂判断或解释真实矛盾的核心章节。
- 来源性质：本项目工作规则
- 理论或方法来源：无外部理论来源；它是防止为所有章节强造冲突的保守默认。
- 本 Skill 改编：内部仍记录本段的内容与观众收获，对外只显示自然中文段落。

## 3. 内部 Section Card

每个章节只选择一种内部组织方式：`STP`、`PEIL`、`VALUE_LOOP` 或 `PLAIN`。禁止在同一章节叠加两套组织方式。

内部固定字段：

```text
section_id:
section_function:
viewer_question:
organization: STP | PEIL | VALUE_LOOP | PLAIN
organization_fields:
core_claim:
claim_type:
evidence_items:
relation_to_previous:
transition_to_next:
estimated_duration_range:
delete_condition:
```

这些字段用于验证和审查，不在默认回复中展示。内部字段按所选方式填写：

- `STP`：`setup` / `tension` / `payoff`
- `PEIL`：`point` / `explain` / `illustrate` / `lesson`
- `VALUE_LOOP`：`context` / `application` / `framing`
- `PLAIN`：`content` / `takeaway`

## 4. 章节推进与删除

每章只承担一个主要功能。相邻章节必须存在可说明的原因、结果、矛盾、升级、证明、反驳、应用或边界关系。章节没有新回报、没有真实材料、只为凑时长或偏离主题时，给出删除、合并或补证路径。

相邻两个章节都没有具体案例、数据、操作结果或画面材料时，标记连续抽象风险。这只是待频道验证的结构风险，不能声称必然导致流失。`AUDIT` 只报告问题与修复路径，不直接删除、合并或重排输入结构。

## 5. 前 30 秒计划

- `0–8 秒`：对齐标题与缩略图的核心承诺；
- `8–20 秒`：明确观众能获得什么；
- `20–30 秒`：说明为什么值得继续，并安排首个真实证明出现的位置。

这只是工程组织方式，不是统一留存定律。不得用自我介绍、频道片头、空洞背景、未经证实冲突或机械念目录填充开头。

## 6. 对外的逐字稿大纲

默认回复把每张内部卡翻译成自然中文段落。每段包含：

- 一个普通人能理解的段落标题；
- 这一段对观众的作用；
- 2—5 个口语化要点，只说明要讲什么，不写成可直接照念的完整台词；
- 需要的例子、证据或画面；
- 怎么接到下一段；
- 预计时长。

不要显示内部卡名、字段名、状态枚举或未解释缩写。资料不足时，在“还需要补充什么”里说清楚缺哪一项，以及它会影响哪一段。
